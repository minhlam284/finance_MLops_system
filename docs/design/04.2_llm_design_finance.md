Finance LLM Design

1. Goal

Thiết kế một use case LLM cho ngành tài chính. Đề xuất: Trợ lý hỗ trợ khách hàng xử lý tranh chấp giao dịch (transaction disputes) và tra cứu chính sách thẻ.
- Yêu cầu: Sử dụng tool call gọi tới Feature Store prediction API.
- Source scope: faq_docs, dispute_policy_docs, gold_ecommerce.obt_transaction_fraud_view (read-only).
- Risk profile: transaction_id/account_id/PAN là dữ liệu nhạy cảm; nguy cơ prompt injection cao.

2. High-Level LLM System Design
End-to-end flow:
1. Khách hàng hỏi: "Tại sao thẻ của tôi bị khóa sau giao dịch T123?".
2. Gateway xác thực auth JWT.
3. System gọi tool (Prediction API) để lấy `fraud_risk_score` hoặc `account_status`.
4. Retrieval layer lấy context từ chính sách bảo mật thẻ.
5. Prompt builder gom toàn bộ thông tin. LLM tạo câu trả lời giải thích dựa trên chính sách.

4. Data and Knowledge Sources Decision
- llm_knowledge_chunks: Lưu policy docs, hướng dẫn xử lý tranh chấp.
- llm_chunk_embeddings: Vector embeddings cho semantic search.

7. Tool Call Contract Decision
- Tool call API để check trạng thái giao dịch.
- Input: `{account_id, transaction_id}`.
- Output: `{fraud_score, status, timestamp}`.

10. Security and Safety Decision
- PII masking cực kỳ quan trọng: PAN (số thẻ tín dụng) phải được che giấu trong logs và prompt (chỉ giữ 4 số cuối).
- Safety filter block các output chứa thông tin nhạy cảm chưa được mask.

14. CI/CD cho LLM Service
Bao gồm track test cho API service, kiểm tra prompt template, và track cho ML pipeline tương tự ML workflow.
